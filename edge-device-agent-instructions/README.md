# Edge Device Agent Instructions

This folder is the integration contract for Python and IoT agents that run on Jetson or simulated edge devices.

It describes how an edge device connects to the Laravel supervision backend, which HTTP endpoints and MQTT topics it can use, what authentication is required, and which local device modules should exist before the device is considered production-ready.

## Current backend state

- Laravel base URL for local development: `http://localhost:8000`
- HTTP edge API prefix: `/api/edge`
- MQTT topic prefix: `drovenai` by default, configurable with `MQTT_TOPIC_PREFIX`
- MQTT broker in Docker Compose: `mosquitto:1883` from Laravel containers, `127.0.0.1:1883` from the host when forwarded
- Current HTTP auth: `X-Device-Token` header using the one-time provisioning token generated by the admin device registration page
- Current MQTT local broker auth: anonymous in local Mosquitto config
- Production MQTT auth target: per-device broker username/password and ACLs
- Current implemented HTTP endpoints: telemetry ingest and media upload
- Current implemented Laravel-to-device MQTT commands: inference, preview start, preview signaling, preview stop, model deployment
- Current inbound MQTT server consumer: `php artisan mqtt:consume`, which validates envelopes, records traces, and dispatches supported domain events.

## Preview/WebRTC rule

Preview is a controlled session, not a raw camera socket. The required sequence is:

1. Laravel asks the edge device for a preview session.
2. The edge device reserves camera resources and responds that it is ready.
3. Laravel/browser and edge exchange WebRTC signaling data.
4. The WebRTC peer connection starts.
5. MQTT continues to carry control/status; WebRTC carries preview media.

See `07-webrtc-preview-signaling.md` for the required handshake.
